# 看板の検出・座標

## 目的
画面上のどこに看板エディタがあっても、キャンバスの左上（物理ピクセル）を見つけ、ボタンの位置を求める。

## 入口
- `Win/BoardFinder.Find` → `ScreenCapture.CaptureAll`（全モニター）→ `Core/BoardLocator.Find`
- 描画中の再確認: `DrawSession.EnsureEditor`（キャンバス + ツール欄だけキャプチャして `BoardLocator.Matches`）

## 原作側の根拠（原作クライアント `ipv3m4.jar` の `interpot.client.board.LotSignBoardView`）
編集パネル（380x400）内の座標:

| もの | 位置・大きさ | キャンバス原点からの相対 |
|---|---|---|
| キャンバス `CANVAS_BOUNDS` | (26,72) 320x240 | (0,0) |
| コマンド欄 `VIEW_LIST_COMMANDS_BOUNDS` | (0,354) 380x46 | (-26,282) |
| 色ボタン `color(argb, 27*col, 16*row)` | 欄内 (5+27col, 8+16row) 27x16 | (-21+27col, 290+16row) |
| ペン 1 / 4 / 8px `pen(n, x, 8)` | 欄内 (145/177/209, 8) 32x32 | (119/151/183, 290) |
| T（文字） | 欄内 (241,8) | (215,290) |
| CLR | 欄内 (273,8) | (247,290) |
| 保存 / キャンセル | 欄内 (310,8) / (310,24) | 使わない（保存はユーザー） |

実機のスクリーンショットで、キャンバス (38,112)、黒ボタン (17,402) — 一致。

ボタンの見た目（`ColorButton.paintComponent` / `BrushSizeButton`）:
- 上がり: 左上 2px 白、右下 2px 灰 (128)、内側 (2,2,w-4,h-4) が色
- 押下: 左上 3px 灰、右下 3px 白、内側 (3,3,w-6,h-6) が色
- → (3..23, 3..12) は常に色、(1,1) は上がり=白 / 押下=灰

起動直後の状態（`EditCanvas.newPage` + ボタン群の既定）: 黒・4px ペンが選択。

## 検出（`BoardLocator`）
1. 黒 `#060606` の画素を走査し、そこが黒ボタンの (13,8) だと仮定して原点候補を出す。
2. 10 色ボタンすべてで、内側 5 点が正確にその色、ベベル 6 点（(1,1),(1,8),(25,8),(13,1),(13,14),(25,14)）が白か灰。
   ベベルの検査がないと ±1px ずれた位置も一致する（上がりボタンは 1px 内側が色なので、ずれると必ずどこかで外れる）。
3. ちょうど 1 つ見つかったら成功。0 個 / 複数は理由を表示。

色は完全一致（許容差 0）。100 % 表示の Java 8（DPI aware）は 1:1 で描くので問題ない。

## 不変条件とテスト
- スクショで (38,112) が 1 つだけ、黒選択・4px ペン選択と判定: `BoardLocatorScreenshotTests.FindsTheEditorInTheUsersScreenshot`（開発環境のテスト）
- ボタンが隠れたら見つからない: `NothingFoundWhenAButtonIsCovered`。模擬画面でも検出: `FindsTheFakeEditor`

## 落とし穴
- ツールは Per-Monitor V2 DPI aware（`app.manifest`）。そうでないと高 DPI 環境でキャプチャ座標が仮想化されてずれる。
- ゲームが DPI 仮想化で拡大表示されている場合（Java の互換性設定など）は色がにじんで検出できない → 失敗として扱う。
- 他のウィンドウ（本ツールの進捗表示を含む）が看板やボタンに重なると検出できない。進捗表示はゲームと重ならない隅に出す。
