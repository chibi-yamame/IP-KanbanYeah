# 画面・CLI

## 画面（`UI/MainForm`、ウィンドウ名「看板屋」、クライアント 744x660、最小 700x600〔外寸〕）
部品は Windows 標準のもの。例外は「描画開始」の緑の塗りと、描画中の赤（下の「描く操作」）だけ。大きさ・1 倍表示は変えない。

### 上の帯（`ToolStrip`、`GripStyle.Hidden`、`RenderMode.System`、テキストのみのボタン）
左から。区切りは `ToolStripSeparator`。ToolTip は `ShowItemToolTips`（下表の「ToolTip」）。
| 項目 | 動作 | キー | ToolTip |
|---|---|---|---|
| 新規 | 空の看板にする（変更があれば確認） | Ctrl+N | 新しい看板を始める（Ctrl+N） |
| 開く | `.kanban` を開く | Ctrl+O | 保存した看板を開く（Ctrl+O） |
| 保存 ▼ | `ToolStripSplitButton`。ボタン = 保存（開いた / 保存したファイルがあれば上書き、無ければ名前を聞く）、▼ のメニュー = 「名前を付けて保存...」 | Ctrl+S / Ctrl+Shift+S | 看板を保存する（Ctrl+S） |
| 元に戻す / やり直し | 今まで通り（`Undo` / `Redo`） | Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z） | — |
| 貼り付け | 今まで通り（`MainForm.Paste`） | Ctrl+V | クリップボードの画像・テキストを看板に置く（Ctrl+V） |
| PNG に書き出す | 旧「PNG 保存」。320x240 の 10 色画像（下書き）を PNG で保存 | — | 描く 10 色の絵を PNG に保存する |
| 使い方 | `Alignment = Right`。「使い方」ウィンドウを開く（下記） | — | 操作のしかた |
- 新規・開く・保存・名前を付けて保存の中身は [boardfile.md](boardfile.md)（`UI/BoardFileCommands`）。MainForm から呼ぶのは `files.New()` `Open()` `Save()` `SaveAs()` と、
  `FormClosing` の `ConfirmDiscard()`、`.kanban` のドロップ（`OpenFile` で `files.OpenPath`）だけ。
- 描画中・フルカラーの書き込み中は、「使い方」以外を無効にする（`UpdateButtons`）。元に戻す / やり直しは今まで通り `CanUndo` / `CanRedo` も見る。
- 貼り付けは押したときにクリップボードを読む（中身に応じた有効・無効の切り替えはしない）。
- 「PNG に書き出す」は下書きが無い / 古いときに作ってから保存する。ペンの入力方式では今まで通り下書きを作って**下書き表示に切り替える**（`ShowDraft`）。
  フルカラーでは表示の切り替えを隠しているので `host.MakeDraft()` だけで作り、表示は切り替えない。ログ `保存しました: <パス>`。

### キー
| キー | 動作 | 文字入力中（TextBox / ComboBox / NumericUpDown にフォーカス） |
|---|---|---|
| Ctrl+N / Ctrl+O / Ctrl+S / Ctrl+Shift+S | 新規 / 開く / 保存 / 名前を付けて保存 | 効く（これらは文字入力で使わない）。描画中は何もしない |
| Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z） | 元に戻す / やり直し | 効かない（欄の普通の動作） |
| Ctrl+V | 貼り付け | 効かない（欄の普通の貼り付け）。描画中は何もしない |
| Esc | 描画中の中止（どのウィンドウが前面でも。[drawing.md](drawing.md)）。看板上では選択解除 | — |
キーは `MainForm.OnKey`（`KeyPreview`）で受ける。看板上の操作（クリック・ドラッグ・矢印・Delete）は `EditorView`。

### 左パネル（上から。`StackPanel`）
1. **看板**（`EditorView`、1 倍 + 周囲 10px の余白）。
2. **表示の切り替えと下書き**（1 行）: `RadioButton`「カラー」「下書き（10 色）」と、`Button`「下書きを作る」（旧「下書き」）。
3. **統計**（1 行の `Label`、`AutoEllipsis`）: 下書きがあれば `ストローク 12,345 本 / 色の切替 9 回 / 目安 1 分 30 秒`。下書きが無い・古い・計算中のときは
   `下書きを作ると、本数と目安時間が出ます`（旧の 2 行の案内文は短くし、残りは「下書きを作る」の ToolTip へ → 下の「ToolTip と使い方に移した文」）。
   旧 2 行目の `塗りつぶし: 黒 → 白 赤 …` は**統計の ToolTip**（マウスを載せたときだけ）に移す。
4. **描く操作**（`GroupBox`、見出し「描く操作」）:
   - 1 行目: `入力方式` + `ComboBox` + `看板を検出`（今まで通り）。
   - 状態の行（入力方式が「フルカラー」のときだけ表示。次の節）。
   - **描画開始**（`Button`、高さ 36）: 通常は**緑の塗り**（`BackColor` `#1F8C3A` = アプリのアイコンの緑、`ForeColor` 白、太字 10.5pt、`FlatStyle.Flat`、`FlatAppearance.BorderSize` 0、
     `MouseOverBackColor` `#197530`、`MouseDownBackColor` `#14602A`）。無効のとき（書き込み中など）は `BackColor` = `SystemColors.Control`、`ForeColor` = `SystemColors.GrayText`（読みやすさのため）。
     **描画中は同じボタンが赤い「中止 (Esc)」**になる（`BackColor` `#C0392B`、`MouseOverBackColor` `#A93226`、`MouseDownBackColor` `#922B21`、白い太字）。別の中止ボタンは無い。
     押すと中止（`drawing?.Cancel()`）。Esc は今まで通り。描画が終わる（中断を含む）と緑の「描画開始」に戻る。
   - 3 行目: 左に**看板の検出結果**（`Label`。最初は `看板: 未検出`。「看板を検出」が成功すると `看板: (38, 112)`、失敗すると `看板: 見つかりません`。ToolTip にウィンドウ名）、
     右に小さい `続きから / 手直し`（`Button`、高さ 24、幅は文字に合わせる）。「看板を検出」のログ（`看板を検出しました: キャンバス左上 (x, y) / ウィンドウ「…」` や失敗の理由）は今まで通り出す。
5. **進捗バー**（枠の外、1 行）。
6. **ログ**（`TextBox`、残りの高さいっぱい）。

描画開始（ペンの入力方式）の流れ・安全装置は [drawing.md](drawing.md)。描画中は枠の「描画開始」（赤い中止）以外の操作を無効にする: タブ・看板・上の帯（使い方を除く）・下書きを作る・看板を検出・続きから / 手直し・入力方式。
進捗はウィンドウタイトル（`看板屋 - 描画 12%`）とゲームと重ならない画面の隅の `ProgressOverlay`（最前面・非アクティブ化・クリック透過）。

### 入力方式
3 つ: バックグラウンド（推奨）/ マウス操作（互換・遅い）/ **フルカラー（直接書き込み・実験的）**（`Modes` の 3 番目、設定 `input` = 2）。フルカラーの詳細は [fullcolor.md](fullcolor.md)。
フルカラーを選んだとき:
- **状態の行**（枠の入力方式の行の下、`TableLayoutPanel` の 1 行。他の入力方式では非表示 = 高さを取らない）: 左に**色の点**（`Label` の「●」）+ **状態の文字**、右に `InterPot を起動`（フルカラー用に起動 = `GameLauncher.Launch`）と、
  その右に隣り合う小さな `▼`（`Button`、幅 22）。`▼` を押すと `ContextMenuStrip`（ボタンの下に表示）が開き、「ショートカットを作成」（デスクトップに .lnk = `GameLauncher.CreateShortcut`）。
  以前の独立した「ショートカットを作成」ボタンはこれに替える。`InterPot3.jar` の場所は表示しない（設定 `fullcolor.jar` → 自動検出 → 見つからなければファイル選択。[fullcolor.md](fullcolor.md)）。
  - 点の色と状態の文字（`AgentLink.StatusChanged` で更新。文字は今までと同じ。色だけに頼らない）:
    | 状態 | 点 | 文字 |
    |---|---|---|
    | `Editor` | 緑 `#2E9E3E` | 接続中: エディタあり |
    | `NoEditor` | 橙 `#E0A000` | 接続中: エディタなし |
    | `Mismatch` | 赤 `#D03030` | 版が合いません |
    | `Busy` | 赤 `#D03030` | 未接続（別の看板屋が使用中） |
    | `Disconnected` | 灰 `SystemColors.GrayText` | 未接続 |
- **隠すもの**（無効ではなく `Visible = false`。詰めて高さを取らない）: 「看板を検出」、検出結果と「続きから / 手直し」の行、「下書きを作る」と表示の切り替え（カラー / 下書き）の行、統計。
  フルカラーに入った時点で表示は**カラーに戻す**（下書き表示のまま隠れて戻せなくならないように）。
  「描画開始」は残り、フルカラーでの説明（旧統計欄の文）「フルカラーで書き込みます（10 色に減色しません。下書きは使いません）」は**描画開始の ToolTip**にする。
  編集の表示は今まで通りカラー。「PNG に書き出す」は下書きを作って保存するだけ（表示は変えない）で使える。
- 「描画開始」→ `StartFullColor`: カウントダウンなし。状態が「接続中: エディタあり」でなければ、ログに理由を出して何もしない（下表）。書き込み中（応答待ち、最大 10 秒）は
  「描画開始」（緑のまま無効の見た目）と編集を無効にする。この間は中止できない（Esc の監視もない）。
- 看板屋を閉じるとき、`AgentLink` は後始末する（接続を閉じ、サーバーを止める）。ゲームは閉じない。

- フルカラーのログ（ASCII でない固定文。接続の変化もログに出す）:
  | 場面 | ログ |
  |---|---|
  | 接続した（初回の HELLO） | ゲームの連携プログラムとつながりました |
  | 切れた | ゲームとの接続が切れました |
  | 状態が `Disconnected`・`Busy`・`Mismatch` で描画開始 | ゲームとつながっていません。「InterPot を起動」でフルカラー用に起動してください（ゲームを先に起動済みなら、一度閉じて起動し直し）／別の看板屋が使用中です／連携プログラムの版が合いません |
  | `NoEditor` で描画開始 | InterPot で看板の編集画面を開いてください |
  | 版違い（接続時に 1 回） | ゲーム側の連携プログラムの版（n）が看板屋と合いません。「InterPot を起動」で起動し直してください |
  | 書き込み成功 | フルカラーで書き込みました。看板を確認して、「保存」はご自身で押してください。 |
  | `ERR none` | エディタが閉じられたため書き込めませんでした |
  | `ERR <理由>` | ゲームがエラーを返しました: <理由> |
  | 応答なし（10 秒） | ゲームが応答しません（接続を切りました） |
  | 起動 | InterPot を起動しました（フルカラー用）。ログインして看板の編集画面を開くと、状態が「接続中: エディタあり」になります |
  | `InterPot3.jar` が選ばれない・Java がない・起動に失敗 | InterPot3.jar が見つかりません／InterPot を動かす Java（.jar を開くプログラム）が見つかりません／起動できませんでした: <メッセージ> |
  | ショートカット | デスクトップにIP起動用リンク「InterPot3 (屋)」を生成しました（パスは出さない） |
  | ショートカットの作成に失敗 | ショートカットを作れませんでした: <メッセージ> |
  | エージェントの jar が内蔵されていないビルド | この看板屋にはフルカラー用の連携プログラム（kanban-agent.jar）が入っていません |
### ログ欄の高さ・その他
- **ログ欄の高さ**（左パネルは上から積み、ログが残りを取る。数字は 96 DPI・Yu Gothic UI 9pt）:
  | 段 | 高さ |
  |---|---|
  | 上の余白 | 6 |
  | 看板（260 = 240 + 余白 10 × 2） | 260 |
  | 表示の切り替え + 下書きを作る | 34 |
  | 統計（1 行） | 22 |
  | 描く操作の枠（見出し・内側の余白 28 + 入力方式 30 + 描画開始 40 + 検出結果 / 続きから 30 + 外側 4） | 132 |
  | 進捗バー | 20 |
  | すき間 | 3 |
  | **ログの上端** | **477** |
  上の帯（`ToolStrip`）は左パネルの外（全幅の上）で、標準の高さ 25px を使う。左パネルの高さ = クライアント高 660 − 25 = 635、下の余白 6 + 3 = 9。
  よって**ログの高さ = クライアント高 − 25 − 477 − 9 = クライアント高 − 511 = 149px**（旧は 660 で 132px〔実測は 138〕。上の帯の 25px を足しても、4 ボタンの行・案内文・中止の行が減って増える）。
  1 行は `log.Font.Height`（Yu Gothic UI 9pt で 16〜18px）なので **約 8〜9 行**（条件の 6 行 ≈ 112px 以下を満たす）。
  **フルカラーモード**: 隠す 3 つ（表示の切り替え行 34 + 統計 22 + 検出結果 / 続きから 30 = 86）を引き、状態の行（30）を足して 149 + 86 − 30 = **205px = 約 11〜12 行**（条件の 5 行 ≈ 94px 以下を満たす）。
  上の帯が 27px になる環境でも 147px / 203px で条件は満たす。最小サイズ（外寸 700x600）では約 50px（3 行）で、旧版も下限の 48px だった。
  実装では 1 行の高さを `log.Font.Height` で確かめ、既定で `6 * Font.Height + 4` 以上、フルカラーで `5 * Font.Height + 4` 以上になること
  （フォントが違って足りなければ起動時にクライアント高を増やす。`MainForm.EnsureLogLines`）。ログの最小高 48px のクランプはそのまま。**ウィンドウの大きさは今回変えない**
  （足りない案が出たら、描く操作の枠の内側の余白を詰める → それでも足りなければ報告）。
- 描画開始から実際の描画までのカウントダウンは 2 秒（`MainForm.CountdownSeconds`、CLI `--countdown` の既定も 2）。
- 編集はフルカラー表示、「下書きを作る」で 10 色の描く絵を作って表示（[features.md](features.md)「入口・流れ」）。描画開始・PNG に書き出すは
  下書きが古ければ作り直してから使う。
- 右: Feature のタブ（`FeatureRegistry`。下地 → 画像 → スタンプ → 文字 → 減色、起動時は下地）。各タブの中身は [features.md](features.md)。
  各タブの説明文は 1 行まで。詳しい説明は ToolTip と「使い方」へ（下記）。
- オブジェクトを選ぶと、それを扱う Feature のタブに切り替わる（`IFeature.Owns`）。
- 貼り付け（Ctrl+V / 上の帯の「貼り付け」、`MainForm.Paste`）: `Clipboard.GetDataObject()` を `ClipboardContent.Read` で読み、画像ファイル →
  画像データ（PNG のアルファは保つ）→ テキストの順で最初に見つかったものを、画像は「画像」タブ・テキストは「文字」タブの Feature
  （`IAcceptsPaste`）に渡す。何もなければログに「貼り付けられるものがありません」。詳細は [features.md](features.md)「クリップボードから貼り付け」。
- ファイルのドロップ（と exe の引数 1 個）: `.kanban` なら看板を開く（変更があれば確認。[boardfile.md](boardfile.md)）。画像なら、表示中のタブが `IAcceptsFiles` ならそこへ、違えば「画像」タブへ。
- 目安時間 = ストローク数 × 方式別の実測値（Post 2.3ms、Send 18ms）+ 色切替 × 0.15 秒 + 2 秒。

### 「使い方」ウィンドウ（`UI/UsageForm`、新規）
上の帯の右端の「使い方」で開く、小さな別ウィンドウ（`Form`、`FormBorderStyle.SizableToolWindow`、`ShowInTaskbar = false`、`Owner` = メインウィンドウ、非モーダル、約 460x420、
最小 320x240、`StartPosition.CenterParent`）。中身は読み取り専用の複数行 `TextBox`（等幅でない通常フォント、背景 `SystemColors.Window`、縦スクロール）に文章だけ。
すでに開いていれば前面に出す（1 つだけ）。Esc で閉じる。設定は覚えない。メインウィンドウが閉じれば一緒に閉じる。文章（この通りに入れる。節の見出し + 箇条書き）:
```
看板を作る
・タブは下から重ねる順です: 下地 → 画像 → スタンプ → 文字。減色は「下書き」の作り方です。
・画像: ボタン、またはウィンドウへのドラッグ&ドロップで開きます。何枚でも置けます。余白・透明部分には下地が見えます。
・貼り付け: Ctrl+V（または上の帯の「貼り付け」）で、クリップボードの画像・文字を置きます。

看板の上の操作
・クリックで選択。ドラッグで移動、角で拡大縮小、上の丸で回転（Shift で 15° ずつ）。
・矢印キーで 1px（Shift で 10px）移動、Delete で削除、Ctrl+Z / Ctrl+Y で元に戻す / やり直し。
・公式と同じ文字は、移動だけできます。

ライブラリ（スタンプ・フレーム）
・クリックで使います。Ctrl+クリックで選びを切り替え、Shift+クリックで範囲、Ctrl+A ですべて選びます。
・Delete キー、または右クリックの「削除」で消します。右クリックの「削除を元に戻す」で、直前の 1 回分を戻せます（確認は出ません）。
・スタンプは 320×240 より大きい画像は登録できません。複数まとめて選べます。
・フレームは登録時に 320×240 にして保存します。色は下書きのときに 10 色にします。

描く
```

## 設定（`UI/Settings`）
`AppPaths.DataDir\settings.txt`（key=value）。全体: `input`（0 = バックグラウンド、1 = マウス操作、2 = フルカラー）, `fullcolor.jar`（`InterPot3.jar` のフルパス。既定は空。空・ファイルがないときは自動検出〔アンインストール情報 → 既定の場所〕、それも無ければファイル選択で選んだ場所を保存 → [fullcolor.md](fullcolor.md)）, `tabName`（前回のタブをタブ名で。順番が変わってもずれない。
旧版の `tab`〔番号〕は読まない）, `board.folder`（看板を開く / 保存するダイアログの前回のフォルダ。[boardfile.md](boardfile.md)）。Feature ごと: `picture.fit`, `folder`（画像）、`dither`, `strength`, `colors`（減色）、
`frame.*`, `stamp.*`, `text.*`。壊れていても既定値で起動する。開いている看板のファイルは覚えない（起動すると空の看板）。

## CLI（`Program.Cli`）
```
KanbanYeah.exe 画像                 … 画面で開く
KanbanYeah.exe 看板.kanban          … 画面で開く（保存した看板）
KanbanYeah.exe --draw 画像 [--fit contain|cover|stretch] [--dither none|fs|atkinson|bayer] [--strength 0-100]
                 [--bg RRGGBB] [--input post|send] [--delay ms] [--click-delay ms] [--fence n] [--retouch n]
                 [--countdown s] [--save-quantized out.png] [--log file] [--debug-shot out.png]
KanbanYeah.exe --board 看板.kanban [--no-draw] [--input post|send] [--delay ms] [--click-delay ms] [--fence n] [--retouch n]
                 [--countdown s] [--save-quantized out.png] [--log file] [--debug-shot out.png]
                                    … 保存した看板を、ファイルの減色の設定で描く（--draw の看板版。--fit/--dither/--strength/--bg は効かない。
                                      --no-draw は計画までで描かない）。詳細は boardfile.md
KanbanYeah.exe --quantize 画像 --save-quantized out.png [オプション]
KanbanYeah.exe --detect
KanbanYeah.exe --compare a.png b.png
KanbanYeah.exe --register-stamp 画像 [--remove-bg]          … 320x240 を超えると終了コード 1
KanbanYeah.exe [--fit ...] --register-frame 画像 [--remove-bg]   … 配置して保存するだけ（減色オプションは効かない）
KanbanYeah.exe --dotfont-dump dir 10-22 chars.txt                         … 公式文字の調査用（GDI の字形を書き出す）
```
終了コード: 0 = 完成（`--compare` は一致、`--no-draw` は計画まで成功）、1 = 一致しない画素が残った（不一致）、2 = 中断、3 = エラー / 見つからない
（`--board` のファイルが無い・壊れている・新しい版もここ。メッセージは [boardfile.md](boardfile.md) の表）。
親コンソールがあれば出力（UTF-8）、`--log` でファイルにも。CLI の `--draw` は画像 1 枚だけ（スタンプ・文字は画面から、または `--board` で保存した看板）。フルカラー（直接書き込み）は画面だけ（CLI なし）。

## 環境変数
| 変数 | 意味 |
|---|---|
| `KANBANDRAWER_DATA` | 設定・ライブラリの置き場所（既定 `%APPDATA%\KanbanDrawer`）。テストはここを差し替えてユーザーのライブラリを汚さない |
| `KANBANDRAWER_PIPE` | フルカラー連携のパイプ名（`\\.\pipe\` の後ろ。既定 `KanbanYeah-<ユーザーの SID>`）。テスト用（[fullcolor.md](fullcolor.md)） |
| `KANBANDRAWER_TRACE` | 描画のトレース（パス・フェンスの待ち時間/タイムアウト・ボタン確認・読み戻し）を追記するファイル |
